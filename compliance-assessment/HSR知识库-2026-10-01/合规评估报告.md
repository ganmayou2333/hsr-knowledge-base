## 一、业务背景与评估范围

本库是一个基于 Obsidian 构建的《崩坏：星穹铁道》数据知识库，由个人（文档中称"Lead"）维护，免费、非商业，面向玩家与同人社区开放。其核心是将游戏的角色、光锥、物品、遗器、模拟宇宙、剧情文本、世界观等公开数据与文本，以中文为基准整理、翻译并关联，形成 `zh_cn` 基准库及 `en_us / zh_tw / ja_jp / ko_kr` 多语言镜像，同时附带通过 GitHub Pages 公开展示的静态 Wiki 站点与一套只读 MCP 工具层。

数据来源主要有四类：hsr.nanoka.cc（粉丝数据库，许可状态待核）、米游社官方 Wiki（官方社区内容，词条声明禁止转载）、官网（官方资料）及 StarRailRes 开源仓库（AGPL-3.0），另有 DimbreathBot/TurnBasedGameData（无许可证，TextMap 文本，仅作参考）与 B 站 BWIKI（社区 Wiki）。抓取方式为浏览器模拟点击加随机间隔，协作准则明确"模仿得像正常人""规避反爬与 IP 封禁"。

本库对代码与编排成果采用 AGPL-3.0 许可，并声明游戏素材与文本版权归 HoYoverse（米哈游），依各地区官方同人指引使用；图标与游戏美术不随仓库分发（`.gitignore` 排除 SRR 克隆与 wiki 生成物），站点在 CI 构建时从 StarRailRes 拉取。

已确认事实包括：项目免费非商业；代码与编排以 AGPL-3.0 开源；游戏素材版权归 HoYoverse；目标覆盖中国大陆、日本、中国大陆与日本以外区域；抓取采用模拟点击与规避反爬策略。待确认事实与分析假设包括：各区域官方同人指引对"数据整理/资料站"型作品的具体涵盖范围；hsr.nanoka.cc 与 DimbreathBot/TurnBasedGameData 的确切许可状态与授权范围；站点构建实际公开展示的游戏素材（高清立绘、游戏字体）范围。本次评估覆盖著作权与再分发、数据抓取与来源授权、开源许可边界、跨境公开与商标使用四个法律问题；不涉及个人信息、未成年人、交易与消费者等维度（本库无相应行为）。

## 二、法律分析

### （一）评估对象与游戏内容权利方：游戏素材的再创作、翻译与再分发授权合规

本库将游戏的剧情文本、角色介绍、遗器来历等文字内容及名称、设定等素材收录、翻译并公开再分发，首当其冲的是 HoYoverse 对上述内容享有的著作权。游戏剧情与文本属于受《著作权法》（2020 年修正，现行有效）保护的文字作品，角色立绘、界面、字体等则构成美术作品，其著作权均归 HoYoverse 所有，本库的 AGPL-3.0 许可并不能改变这一归属。本库对游戏素材的利用，其合法性基础主要来自官方同人指引这一授权框架，而非《著作权法》第二十四条的合理使用：该条第一项"为个人学习、研究或者欣赏"仅适用于个人用途，本库向公众开放站点、允许再分发，难以落入该豁免；第二项"为介绍、评论……适当引用"也仅适用于以介绍评论为目的的有限引用，不涵盖将游戏文本成体系收录进一个可再分发的知识库。因此，本库是否合规，核心取决于是否满足各区域官方同人指引设定的条件。

中国大陆现行有效的《崩坏：星穹铁道》同人衍生作品创作指引 V3.0（2025-07-15）允许用户对已公开发表内容进行二次创作并发布至其他网站，但有三项关键限定：其一，该许可排除"任何纯搬运的行为"，要求使用素材进行二次创作而非单纯搬运；其二，仅限"非商业性质的个人使用"，并在使用素材时放置「© 米哈游版权所有」标识及"《崩坏：星穹铁道》素材的权利归米哈游所有，其他内容的相关权利、利益均归各自所有者享有"的法律声明；其三，官方未公开的素材不得使用。本库整体上对数据进行了翻译、结构化编排、双链关联与多语言加工，通常可认定具有二次创作与实质性整理成分，而非"纯搬运"；但其正文大量直接再现游戏原文（如剧情文本、角色故事），对这部分而言，若属全文照录而无再创作，则存在被认定为"纯搬运"的边界风险。在版权标识上，本库 README 版权声明节虽已写明"游戏名称、角色、美术资源及文本版权归 HoYoverse（米哈游）所有"，但并非指引要求的「© 米哈游版权所有」标准标识与完整法律声明措辞，站点页脚亦然，属于未完全对齐指引条件的缺口。

中国大陆与日本以外地区适用的《Honkai: Star Rail Fan Creations Guide》v2.0（2024-08-23）同样允许非商业个人使用已公开素材进行二次创作并发布于网站，同样排除纯搬运并要求放置版权标识；其明确不适用于中国大陆简体中文版与日本版，故本库英文、繁体中文、韩文镜像的公开应遵循该指引的上述条件。日本区域则适用《崩坏：星穹铁道》二次创作指南（miHoYo / COGNOSPHERE），该指南在允许插图、小说、视频等非营利二次创作的同时，明确禁止对官方素材的直接二次利用与描改（トレース），对"数据搬运/资料库"型使用未设明确许可通道。本库日文镜像在 GitHub Pages 上向日本用户公开，若将游戏文本、设定整理收录视为"对官方素材的直接二次利用"，则可能落于该指引禁止之列，此点受日文指引文本与日本法解释影响，需当地专业人员确认。

综上，就著作权维度，本库在大陆及其他区域因非商业、免费且附有版权归属说明，总体落在授权框架内，但存在"纯搬运"边界与版权标识未对齐两个可整改缺口；日本区域则存在需要确认的直接素材再利用风险。

依据：《中华人民共和国著作权法》（2020 年修正）第二十四条、第四十九条；《崩坏：星穹铁道》同人衍生作品创作指引 V3.0（2025-07-15）；《Honkai: Star Rail Fan Creations Guide》v2.0（2024-08-23）；《崩坏：星穹铁道》二次创作指南（日本）。

### （二）评估对象与数据来源方：数据抓取行为与来源授权合规

本库通过浏览器模拟点击、随机间隔并明确"规避反爬与 IP 封禁"的方式，从 hsr.nanoka.cc 与米游社官方 Wiki 抓取数据。这一抓取行为主要受《反不正当竞争法》（2025 年修订，2025-10-15 施行）第十三条第二款规制，该款禁止经营者以欺诈、胁迫、避开或者破坏技术管理措施等不正当方式，获取、使用其他经营者合法持有的数据，损害其他经营者合法权益、扰乱市场竞争秩序；同时《著作权法》第四十九条禁止故意避开或破坏权利人为保护作品采取的技术措施。需要指出的是，反不正当竞争法的规制主体是"经营者"，且要求以"损害其他经营者合法权益、扰乱市场竞争秩序"为要件，司法实践中（如最高人民法院指导性案例 262 号）对"实质性替代"型数据搬运方认定不正当竞争。本库系个人非商业用途、对抓取数据作整理加工而非直接替代原数据站，通常难以被认定为经营者实施实质性替代的竞争行为，故整体触发该条款执法与诉讼的概率较低。但协作准则中"规避反爬与 IP 封禁"的表述，若被抓取方设置了反爬技术措施，则可能构成"避开技术管理措施"的负面情节，且明确写入文档会固定不利证据，属于应当调整的低中风险缺口。

就各来源的授权状态：StarRailRes 为 AGPL-3.0 开源仓库，本库对模拟宇宙 JSON 数据的获取与再整理具备许可基础；米游社官方 Wiki 为官方内容，其词条声明"禁止转载"，本库提取其中属性、数值等事实性数据并作结构化整理，事实与思想不受著作权保护，但若直接复制词条的文字表达则可能构成转载或侵权，需区分处理；hsr.nanoka.cc 站点未见许可声明，其作为粉丝库抓取其数据，权利来源不清；DimbreathBot/TurnBasedGameData 无许可证，按默认规则保留所有权利，本库已如实披露"仅作参考、派生译文仅用于非商业整理"，但使用无授权来源派生内容仍存在权利瑕疵，且在公开再分发时会被放大。上述来源中，无许可证与许可待核来源的使用，是本库数据来源维度的主要合规缺口。

依据：《中华人民共和国反不正当竞争法》（2025 年修订）第二条、第十三条第二款、第二十九条；《中华人民共和国著作权法》（2020 年修正）第四十九条、第五十三条；最高人民法院指导性案例 262 号（2025-08-27 发布）。

### （三）评估对象与第三方使用者：AGPL-3.0 许可范围与游戏素材权利的边界

本库以 AGPL-3.0 许可"本项目内容"，并声明因派生自 AGPL-3.0 的 StarRailRes 而必须同许可。就开源合规本身，该选择符合 AGPL 的强 copyleft 要求，本库对代码、脚本与编排成果以 AGPL-3.0 开源、保留署名并公开仓库，已满足该许可在分发与网络服务提供源码（§13）层面的主要义务。问题在于，本库的"内容"并不限于代码与编排，还包含大量 HoYoverse 享有著作权的游戏文本与数据。AGPL-3.0 第五条规定授予接收者复制、修改、再分发的权利，若将该许可直接覆盖到含游戏素材的"本项目内容"，则在文本上形成"本库授权第三方自由再分发游戏素材"的假象，而实际权利仍属 HoYoverse，第三方依据该许可再分发游戏文本可能侵害 HoYoverse 权利并反受追责。本库已在 NOTICE 第三节明确"游戏素材权利仍属 HoYoverse、AGPL 仅覆盖整理与编排工作"，这在一定程度上缓解了误导，但 LICENSE 文件本身仍是未加限定的 AGPL-3.0 标准文本，"使用与许可"一节"任何人都可自由使用、复制、修改、再分发本项目内容"的表述与素材权利边界并存，易使第三方误解许可范围。

由此形成的风险属于典型的"许可范围超出实际权利"问题：一是可能误导第三方使用者，使其在未遵守 HoYoverse 同人指引的情况下再分发游戏素材；二是若本库以 AGPL 授权其无权处分的素材，则该部分授权自始存在权利瑕疵。整改方向是在 LICENSE 或显著位置明确 AGPL-3.0 仅适用于本库的代码、脚本与编排成果，游戏文本、素材与数据本身不在该许可授权范围内，其使用须另行遵守 HoYoverse 同人指引；并对"本项目内容"的表述作相应限缩，避免在许可文件与使用说明之间产生歧义。

依据：《GNU Affero General Public License v3.0》第五条、第十三条；《中华人民共和国著作权法》（2020 年修正）第九条。

### （四）评估对象与境外公众：多法域公开、境外托管与商标使用

本库的多语言镜像与公开站点使内容同时面向中国大陆、日本及中国大陆与日本以外地区的公众，需分别满足各区域指引（见本节（一）），其中日本区域指引对官方素材直接再利用的限制构成最高约束点，日文镜像的合规性需单独确认。就数据存储与传输，本库通过 GitHub 及 GitHub Pages 托管，数据与站点实际存储于境外基础设施；由于本库收录的是游戏公开数据与文本，不涉及个人信息、重要数据，故《数据安全法》《个人信息保护法》下的数据出境合规风险较低，但若未来收录任何可识别个人的信息，需另行评估。

在商标使用上，本库在名称、README 与内容中使用"崩坏：星穹铁道""星穹铁道"等游戏名称与商标，属对他人有一定影响的名称、网页标识的使用。官方同人指引允许非商业性质的描述性使用，且本库已明确声明为"非商业同人整理"、非官方，未暗示官方关联或合作，一般不构成《反不正当竞争法》第七条规定的混淆行为；但站点若未持续、显著地标明非官方属性，或未来出现商业化，则可能触发混淆与假冒官方之虞，需保持非官方声明的持续可见。

依据：《中华人民共和国反不正当竞争法》（2025 年修订）第七条；各区域官方同人指引（同上）。

## 三、待专业人员确认事项

1. **"纯搬运"边界的定性**：本库正文大量直接再现游戏原文（剧情文本、角色故事等），该部分是否属官方指引禁止的"纯搬运"、抑或因其整体整理翻译而属允许的二次创作，需结合具体收录方式判断，建议由知识产权律师结合样本确认。
2. **日本区域指引的涵盖范围**：日文镜像与公开站点在《崩坏：星穹铁道》二次创作指南（日本）下，数据搬运型整理是否落入"官方素材直接二次利用"之禁止，需日本法域或 COGNOSPHERE 指引的专业确认。
3. **数据源许可状态**：hsr.nanoka.cc 的确切许可状态与授权范围，以及米游社官方 Wiki"禁止转载"条款对本库提取整理的影响，需核实原始来源或向来源方确认。
4. **无许可证数据源**：DimbreathBot/TurnBasedGameData 的 TextMap 文本及派生译文的使用权利基础，需确认是否存在授权或应停止使用。
5. **站点素材范围**：Wiki 构建时从 StarRailRes 拉取并在站点公开的高清角色立绘、光锥图、游戏字体（RPG_CN.ttf 等）的实际范围，需由研发确认构建产物，再评估字体与美术素材的版权风险。

1. **对齐版权标识**：按大陆指引与 Fan Creations Guide 要求在 README 版权声明、NOTICE 与站点页脚统一补充「© 米哈游版权所有」标识及"《崩坏：星穹铁道》素材的权利归米哈游所有，其他内容的相关权利、利益均归各自所有者享有"声明，由知识产权或开源合规角色在一周内完成并同步至所有语言版本。
2. **限缩许可范围**：在 LICENSE 文件或显著位置明确 AGPL-3.0 仅适用于代码、脚本与编排成果，游戏文本、素材与数据不在授权范围内、须另行遵守 HoYoverse 同人指引，由知识产权或开源合规角色修订并同步 NOTICE。
3. **调整抓取行为**：删除或改写协作准则与数据来源说明中"规避反爬与 IP 封禁"的表述，改为遵守各来源 robots、服务条款与合理频率，由研发或架构角色按来源授权调整抓取方式。
