## 三、入库边界（四条铁律）

1. **图片零入库**：`icon/`、`image/`、`font/`、`wiki/assets/icons/`、任何 `PNG/JPG` 均不入库（D-014/D-015）。
2. **生成物零入库**：`wiki/pages/`、`wiki/data/` 由 `build_wiki.py` 生成。
3. **第三方克隆零入库**：`StarRailRes-*`、`Mar-7th_StarRailRes/`、`.srr/`。
4. **临时与私人内容零入库**：`.tmp_*/`、`temp/`、`.obsidian/`、`docs/对话记录.xml`；**来源受限内容**（`*/quest/剧情文本/`）本地保留但不入库（D-025）。

## 四、提交纪律

- 分组提交：`git add <明确路径>`；**禁止 `git add -A`**。
- `--force` 仅用于历史重写后，且必须 `--force-with-lease`。
- 提交前必跑：`python scripts/verify_links.py`（死链 0）、`python wiki/build_wiki.py`（构建成功、`link_report.dead = 0`）。
- 字段完整性：`cd zh_cn && python ../scripts/verify_fields.py`（已知待补充 156，不得新增）。

## 六、本机 git 配置（易被清理误伤，务必知悉）

| 配置 | 值 | 说明 |
|---|---|---|
| `http.sslBackend` | `schannel` | **使用 Windows 证书存储**。2026-10-02 前的 `openssl + http.sslCAInfo=G:\HSR\temp\win_certs.pem` 指向 `temp/` 内的本机 CA 包；该目录清理后 push 直接失败（`error setting certificate file`）。schannel 不依赖仓库内文件，**不会再被清理误伤** |
| `http.postBuffer` | 524288000 | 大仓库推送缓冲 |
| `http.version` | HTTP/1.1 | 兼容性 |

> **纪律**：任何"本机运行依赖的文件"**不得放在 `temp/` / `.tmp_*/` 等会被清理的目录**。若确需仓库内文件（如自定义 CA），放仓库根 `.certs/` 并保持 gitignore，同时在本文登记。
