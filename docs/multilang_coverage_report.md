## 结论与规划

- StarRailRes index_new 五语言（cn/cht/en/jp/kr）同量，**官方数据源对 P0/P1 目录提供 100% 覆盖**。
- 生成方式：以现有 cn md 为模板，用各语言 JSON 回填 名称/描述/技能/星魂 等文本字段，生成 zh_tw/en_us/ja_jp/ko_kr 目录。
- 无 ID 元信息的索引/评级文件：多语言化时按 名称映射（文件名）生成索引副本或标注跳过。
- md 有但 JSON 无的 ID：人工核对（可能为联动/活动/未收录条目），标注「待补充」。
- JSON 有但 md 无的条目：说明 md 数据库未收录该条目，本次不反向生成。

### md 数据库结构（简体基准）
- **角色** character/：`命途/角色名_属性_星级.md`，含 基本信息表（名称/命途/属性/稀有度/阵营/介绍/定位）/ 配音演员表 / 基础属性表 / 晋阶材料 / 技能材料 / 技能详情 / 星魂
- **光锥** lightcone/：`命途/光锥名.md`，含 基本信息表 / 背景故事 / 基础属性 / 叠影效果 / 晋阶材料
- **遗器** relic/：`部位/套装名.md`，含 基本信息 / 套装效果 / 部位属性
- **物品** items/：`类型目录（英文）/物品名.md`，含 基本信息表（名称/用途/评级/类型）/ 说明 / 获得途径
- **模拟宇宙** simulated/：`祝福|奇物|事件|区块|差分宇宙` 子目录，祝福/奇物按星级或名称组织，**多个 ID 同名合并为一个文件**（如奇物万识囊=18/64/1064/3064；祝福 BCI-34型灰质=612830/615830），多语言化必须按「名称→ID 集合」匹配

1. **P0（character/lightcone/relic）**：按实体ID直查 JSON，回填 名称/介绍/技能/星魂/叠影 文本
2. **P1（items/simulated）**：items 按 ID；祝福/奇物/事件按「名称→ID 集合」匹配，多 ID 合并文件的每个 ID 分别回填

4. 目标目录：`zh_tw/` `en_us/` `ja_jp/` `ko_kr/`，镜像 cn 目录结构，文件名用目标语言名称
5. 校验：生成后统计每语言文件数与覆盖字段，输出到本报告更新
