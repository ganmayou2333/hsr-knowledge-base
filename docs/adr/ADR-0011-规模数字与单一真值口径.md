# ADR-0011 · 规模数字与单一真值口径

> **Status**：Accepted（2026-11-15 聚合定稿；D-068 为最近一次修订）
> **覆盖决策**：D-012、D-048、D-059、D-067、D-068
> **相关**：`docs/metrics.md`、`scripts/gen_metrics.py`、`tools/verify_site.py` `[16]`

## Context

规模数字是本库最容易被证伪的一类陈述。盘点实测：同一时点文档里出现过 6668 / 6685 页、93 / 94 角色、1594 / 3829 物品、169 / 172 光锥、62 / 64 遗器——全部是**不同口径混写**，而不是单纯过期。
更隐蔽的是「口径内部错误」：D-059 中「差分宇宙 758 → 769」被当成修正，实际 769 是「递归 770 只减了 1 个索引」的回归，正确值是 758（该目录实有 12 个索引文件）；D-062 中盘点脚本把 3 个写「实体ID：无（官方未公开）」的条目误按名字排除，得 3827，正确值 3829。

## Decision

1. **一个真源**：`docs/metrics.md`（由 `scripts/gen_metrics.py` 生成，44 个 key）是唯一真值；文档里的规模数字由 `tools/verify_site.py` 的 `[16]` 项校验，**改数字必须重跑生成器，不得手改**。
2. **三种口径并存且必须标注**：
   - 详情口径 = 含 `> 实体ID：` 且排除索引 / 分组文件（与 `verify_fields` 同源）→ 用于各分类行；
   - 合计口径 = 目录下全部 `.md`（含索引）→ 仅用于 `data/zh_cn/` 合计行，加 `≈`；
   - 入库 / 工作区口径 = `git ls-tree` vs `find` → 镜像规模对外报**入库数**，工作区数括注（D-068）。
3. **两类口径不得相加**：合计行与分类行不是同一集合，README 明写「故两者不直接相加」（D-012）。
4. **异常值先怀疑口径**：任何「总数对不上」的发现，第一步是列出该目录全部索引文件并复算扣减项，不得直接改数字（D-059）。
5. **生成器只读**：`gen_metrics.py` 不修改任何数据文件，唯一写盘 = `docs/metrics.md`，且除「生成时间」一行外逐字节幂等。
6. **enemies 详情恒为 5**：计数顺序固定为「先排除类别主索引，再累计详情」（D-067）；索引文件写「不适用」使机械计数不再误算。

## Consequences

- **正面**：数字漂移从「靠人记得改」变成「构建即失败」；口径争议有唯一裁判物。
- **负面**：任何文档改数字都要连带跑生成器 + 构建 + 全量验收，单项改动成本上升。
- **风险**：生成器自身若判据写错（D-062 的先例），会把错误固化成「真值」；因此判据变更必须单独提交并附复算证据。
