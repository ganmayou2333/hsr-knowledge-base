# ADR-0012 · 验收器与工具链

> **Status**：Accepted（2026-11-15 聚合定稿）
> **覆盖决策**：D-009、D-030、D-040、D-043、D-044
> **相关**：`tools/verify_site.py`、`scripts/verify_fields.py`、`scripts/verify_links.py`、`scripts/gen_metrics.py`

## Context

「已通过验收」在本库是最高级别的断言（权威层级第 1 级），因此验收器本身必须可靠、可复跑、失败即非零退出。历史上工具链出过四类问题：

1. **退出码缺失**：`verify_links.py` 早期只打印不返回，导致「exit 0」不是断言；
2. **判定面与文档不符**：视觉约束文档写 3 项 / 4 项，校验器实跑 6 条正则；
3. **生成器假设失效**：`build_wiki.py` 未做 URL 编码，含全角引号的文件名可能破链（D-030）；
4. **禁词扫描误伤**：把游戏原文里的「绕过」当违规删除，等于破坏官方文本（D-040）。

## Decision

1. **每个验收器必须有退出码**：数据区死链 > 0 → 非零；规模数字不一致 → 非零；字段异常 > 0 → 非零。判据只认命令输出与退出码，不认描述。
2. **判定面唯一且可定位**：视觉约束由 `verify_site[5]` 的 `check_banned()` 执行，文档引用必须附「判据 → 函数/行号」映射；术语统一为六禁（见 ADR-0002）。
3. **禁词扫描须分范围**：声明类文档（根规范 / `README`）命中即改；数据正文里的普通动词是官方原文，**严禁删除**，只做登记（D-040）。
4. **链接一律 URL 编码**：生成器对链接目标做 `urlencode`/`quote`，并在 Pages 构建后跑一次死链校验（D-030）。
5. **不入库目标走优雅降级**：目标不在页面集时，`md_link` / `wikilink` 输出「（本站未收录）」纯文本，不生成死链、不使构建失败（D-044）。
6. **工具分层**：MCP 只读工具层（9 工具）独立成仓 `markdown-kb-mcp`；写入类工具须单独放行（D-009）。本地实验性工具（如 MediaWiki 演示实例）放 `.tmp_*` 不入库，脚本入 `tools/`（D-043）。

## Consequences

- **正面**：任何结论都能被第三方用一条命令复现；死链 / 数字 / 字段三类回归有机械兜底。
- **负面**：一次提交要跑 4 个脚本（`gen_metrics` / `build_wiki` / `verify_site` / `verify_links` + `verify_fields`），耗时以分钟计。
- **风险**：验收器的 cwd 敏感（`verify_fields` 必须在 `data/zh_cn/` 下跑），跑错位置会把 6,685 扫成 30,675 并给出假结论——因此命令写法在规范里被固定为一行可复制形式。
