# ADR-0010 · 目录扩展与索引体系

> **Status**：Accepted（2026-11-15 聚合定稿）
> **覆盖决策**：D-010、D-039、D-041、D-049、D-062
> **相关**：`格式规范与要求.md` §一 / §十六 / §十八、`docs/仓库结构.md`

## Context

库的类别从 8 个扩到 13 个（新增 `events/` `enemies/` `stages/` `货币战争/` `音乐/`），每次扩展都伴随同一类回归：**生成器与校验器的白名单没跟上**。
两次实证：D-041（`build_wiki.py` 硬编码 11 个顶层目录，新增 `enemies/`、`音乐/` 后死链 9）；D-049（`verify_fields.py` 的 `skip_dirs` 仍按类别名硬排除 `货币战争`，该目录 7 个文件从未被校验）。
另有口径问题：新增类别是否一律四级索引？实测定论——`events/` `enemies/` `stages/` 为三级（无评级层），遗器为三级，角色 / 光锥 / 物品为四级。

## Decision

1. **扩类别须同时改四处**：目录树（规范 §一）、索引层级、`build_wiki.py` 顶层目录（**动态推导**，不得硬编码）、`verify_fields.py` 的类别规则（**按元信息门判定**，不得按目录名跳过）（D-010 / D-041 / D-049）。
2. **索引层级按类别定**：角色 / 光锥 / 物品 / 祝福 = 四级（主 → 分类/命途 → 评级 → 详情）；遗器 / 活动 / 敌人 / 关卡 / 奇物 / 事件 / 区块 = 三级；空评级索引不建、空类型目录不建。
3. **音乐类目为二级起步**：`音乐/音乐.md` 主索引 + `音乐/<专辑名>.md` 详情，子类型文件夹待官方发行自然分类勘察后再定稿（D-039）；红线是专辑名 / 曲目名 / 日期必须有官方出处。
4. **规模数字与目录结构解耦**：目录调整（如 `enemies/` 由扁平下沉为 4 个类型子目录）不得改变详情数口径——`enemies` 详情恒为 5（D-062 / D-067）。
5. **新增类别要能被站点收录**：类目白名单从 `data/zh_cn/` 实际子目录推导，新增目录零改动即可建页。

## Consequences

- **正面**：扩展类别不再需要改生成器；校验覆盖完整（6,685 个文件全扫）。
- **负面**：动态推导意味着「意外出现的目录」也会被建站——需要靠 `.gitignore` 与临时目录纪律兜底。
- **风险**：类型索引会带来一次性的链接重写（`enemies/` 下沉即改 6 处）；此类结构变更必须独立成单，不与内容更新混提交。
