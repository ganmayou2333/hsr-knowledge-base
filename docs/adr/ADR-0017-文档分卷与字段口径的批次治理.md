# ADR-0017 · 文档分卷与字段口径的批次治理

> **Status**：Accepted（2026-11-15）
> **覆盖决策**：D-075、D-076
> **相关**：`ADR-0004`（日志规范）、`ADR-0010`（目录与索引）、`ADR-0011`（口径与数字）

## Context

文档优化原本分三批：批 1 事实校正（已完成）、批 2 缺类型补齐（GLOSSARY / ADR / 总入口，已完成）、批 3 结构拆分（`update.md` 分卷 + `待办清单.md` 拆 `docs/backlog` + `docs/archive`）。
批 3 在第一次执行时被叫停，理由是**「文档内容还没写好就先动 docs 结构」**——顺序反了：结构先行会让读者按新骨架去找不存在的内容。
同期还暴露另一类「顺序问题」：`data/zh_cn/worldview/剧情时间线.md` 的「新角色」字段在不同版本里混用了两种口径（官方「全新角色」= 卡池口径 vs 剧情登场口径），23 个版本存在差异，但多数不是错，而是**字段定义没写死**。

两件事的共同点：**结构 / 字段的改动必须等语义稳定、口径钉死之后再做**，否则会出现「迁移完再改内容」的双倍返工。

## Decision

1. **批 3 重启但范围收窄**（D-075）：只把 `update.md`（1,659 行）按时间分卷迁入 `docs/log/`；`docs/backlog/`、`docs/archive/` 与目录树**一律不动**。理由：日志是纯体积问题、零语义风险；台账与归档涉及分类口径，等内容线补齐再评估。
2. **分卷不改口径**（D-075 + D-072）：`update.md` 仍是「最近条目 + 分卷索引」，索引只写**纯文本路径**，不加链接、不加 URL；分卷文件保留原章节标题与时间戳，按原样搬迁，不重写措辞。
3. **字段口径先定义、再批量校正**（D-076）：`剧情时间线` 的「新角色」= 该版本官方更新说明「全新角色」所列**可玩角色**（卡池口径）；剧情登场信息写入同单元「主要事件」正文，不占该字段。校正以官方更新说明为准，逐版本可复算。
4. **批次准入条件**：任何结构性迁移开工前必须满足两条——① 内容已定稿（不再有批量内容改动在排期）；② 目标口径已写入 `D-*`（不是只在工单里描述）。缺一条则只做「零语义风险」的子项。

## Consequences

- **正面**：避免结构先行使读者迷路；日志体积问题低成本解决；时间线字段从此有唯一定义，后续版本只需按官方公告填。
- **负面**：`docs/backlog/` 与 `docs/archive/` 长期缺席，`待办清单.md`（947 项快照）仍是一份大文件。
- **风险**：分卷后 `update.md` 与 `docs/log/*` 可能出现「同一事件两处记」；因此规定**只有当前月留在 `update.md`**，跨月即迁，且迁出后不保留副本。
