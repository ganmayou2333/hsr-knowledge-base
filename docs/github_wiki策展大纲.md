## 二、各页内容要点

### 1. `Home`
- 一句话：**《崩坏：星穹铁道》非官方数据知识库 —— 以官方本地化文本为准的中文资料整理。**
- 规模块（每轮实测刷新，**不得手改数字**）：`zh_cn` 页数、五语言总量、最后更新时间。
- 分类导航：角色 / 光锥 / 遗器 / 物品 / 模拟宇宙 / 剧情 / 活动 / 敌人 / 关卡 / 音乐 / 规则 / 货币战争 / 世界观 → 全部外链 Pages。
- 声明：非官方、非商业、与 HoYoverse 无关联。

### 2. `项目简介`
- 目标与边界：**只收官方内容**；缺失写「待补充 / 无（官方未公开）」，**不建占位、不机翻**。
- 不是什么：不是攻略站、不是二创聚合、不提供下载。
- 仓库结构一句话 + 指向 `docs/仓库结构.md`。

### 3. `许可与合规`
- **代码层** AGPL-3.0（派生自 StarRailRes 的强制要求）；**内容层** 标注口径见 D-018；游戏数据受官方同人指引管辖。
- `LICENSE` 为标准 AGPL 正文，**不得改动**；限缩声明写在 `README` / `NOTICE` / `数据来源.md`。
- **图片零入库**（图标由 CI 构建期生成，见 D-014/D-015）。
- 禁词红线口径（D-040）：只约束声明类文案，不约束游戏原文。

### 4. `数据来源`
- 官方来源清单 + 每类的具体来源页；版本基线 **4.6**，收录口径统一日期。
- 明确「只取事实数据」的最低风险路径。

### 5. `贡献指南`
- 命名与字段规范（指向 `格式规范与要求.md`）；
- 双链写法 `[[zh_cn/<路径>|<显示名>]]`（表格内转义 `\|`）；
- **提交前必跑**：`python wiki/build_wiki.py`（dead 0）、`python scripts/verify_links.py`（exit 0）、`cd zh_cn && python ../scripts/verify_fields.py`（异常 0）；
- 提交纪律：显式路径 `git add`，禁用 `git add -A`；**发布用构建必须在纯净检出里验收**（D-044）。

### 6. `更新日志`

## 三、落地前置（两件都必须你先做）

1. **仓库可见性**：Wiki 可见性**随仓库**——要公开 Wiki，仓库必须先 **Public**（或账号升 **Pro** 后私有亦可）。
2. **启用 Wiki**：Settings → Features → 勾选 **Wikis**；随后创建 `Home` 页（GitHub 会自动建仓库 `…wiki.git`）。

## 四、纪律（写进运行后的维护约定）

- **Wiki 不放正文**：一旦开始搬正文，就会撞上 5,000 软上限与扁平重名（见评估文档 §三）。
- **数字以实测为准**：`Home` 的规模数字每轮由脚本刷新，不手写。
- **单一真相仍在 vault**：Wiki 只是门面，改动一律先改 `G:\HSR` 再同步。
