局限与风险：

1. 转储未标版本，无法证明某条记录属于哪个游戏版本；「含 4.7 内容」仅依据本任务给定说明与内容比对，不构成版本声明。
2. `Rank` → 本库类型是**本库自定口径**（Minion / MinionLv2 → 普通敌人；Elite → 精英敌人；LittleBoss → 首领；BigBoss → 周本BOSS），官方未公开这层对应关系，故页面一律写成「第三方游戏数据 Rank=…，官方未公开，游戏内仍待核」。
3. `turnbasedgamedata/` 不入库：本轮工作区里 `.gitignore` 已含 `turnbasedgamedata/`（该改动来自同批其他任务，**不在本任务写入范围，本任务未改 `.gitignore`**）；写本文时以现存工作区为准，若该改动被撤回，则 2.7 GB 数据存在误入库风险。
4. 本文引用的 nanoka 数据来自 `https://static.nanoka.cc/hsr/4.7.51/monster.json`（本机快照在 `.tmp_build/nanoka/monster.json`，该路径不入库）。

## 二、方法

1. **名称解析**：`MonsterConfig.MonsterName.Hash` → `TextMapCHS[str(hash)]`；模板名同理。
   解析失败 1 条记录（100204004/1002040），不计入唯一名称。
2. **名称归一化**：NFKC 兼容形式归一 → 中间点 `·` `•` `‧` `∙` 统一为 `·` → 去除所有空白字符。归一化只用于**比对候选**，不构成实体同一性证明；逐字同名与「仅归一化后才同名」分开统计。
3. **Rank 映射**：见上一节第 2 条；同一名称可能同时出现在多个 Rank（本库类型）下，故「名称-类型对」总数可大于唯一名称数。
4. **基础模板 ID 选择**：只考虑 `MonsterID == MonsterTemplateID` 的记录（同一模板的其余记录是同模板下的子记录）。某名称的基础记录**恰为 1 条**时，该 ID 才可作为实体 ID；否则不猜。
5. **比对对象**：默认 `git ls-files zh_cn/enemies`（跟踪口径）；`--include-untracked` 改为工作区扫描（含尚未入库的详情）。本文件除特别标注外为**工作区口径**。
6. **变体**：名称含（完整）（幻象）（污染）（错误）的视为**战斗变体名**，不按名称合并、不据此新建或删除页面；本轮共 98 个变体名。

## 五、分类冲突处置：狂兽的胚芽

- 原状态：置于 `zh_cn/enemies/首领/`，`类型` 写「待核实」，实体 ID 为「无（官方未公开）」。
- 复算：本地转储中该中文名的全部 MonsterConfig 记录均对应 MonsterTemplateConfig `MinionLv2`（本库映射 → 普通敌人）；nanoka 4.7.51 的同名记录 5032010、5032011 也都是 `MinionLv2`。两处独立第三方数据一致，因此原「首领」分类无依据。
- 处置：文件移动到 `zh_cn/enemies/普通敌人/`；类型改为「普通敌人（第三方游戏数据 Rank=MinionLv2，本地转储与 nanoka 4.7.51 两条同名记录一致；官方未公开分类，游戏内仍待核）」；实体 ID 取 **5032010**；弱点按 StanceWeakList 填 火 / 风 / 虚数；数据来源行补 nanoka 5032010、5032011 与本地转储交叉核验（注明版本未标注）；更新时间 2026-11-28。
- **例外说明**：该名称的基础记录（MonsterID == MonsterTemplateID）有两条（5032010、5032011），按 §2 第 4 条本不应指定唯一实体 ID；本轮按任务要求取 5032010。两者关系（同敌人不同模板 / 不同战斗场合版本）**待核**，不在页面中臆断。
