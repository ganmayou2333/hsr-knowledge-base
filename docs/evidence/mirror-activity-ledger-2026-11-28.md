## 三、缺失与未覆盖

- 按上表对应线索，简中 12 个活动详情在四语各有 1 个对应文件，**缺失 0**；英文、日文、韩文缺活动索引（各 0 个），繁中有 2 个索引。
- **未核对**：活动名称以外的字段（开放/结束时间、参与条件、奖励、玩法细节）、正文来源、译文质量、与简中的逐字段差异。部分收录页只列公告字段；带 `L` 的旧页是非官方本地化，也不能据此判断同步。
- **未覆盖**：活动没有数字 ID，本台账不能给出「覆盖率」；它只给出文件存在与对应线索。若要判断覆盖完整，需要逐页建立中文基准、官方原文链接、字段差异与核验日期。

## 五、复核方式

- 文件清单：`git ls-files 'zh_cn/events' 'en_us/events' 'zh_tw/events' 'ja_jp/events' 'ko_kr/events'`；或按 §一 的目录逐项列出。
- A 类链接：在镜像页搜索 `[[zh_cn/events/版本活动/`，命中的目标即该页自述的简中基准；本台账只记录链接存在，不判断历史输入是否就是该文件。
- 页首提示与标记：`python -X utf8 scripts/audit_mirror_marking_coverage.py`（events 行同时给出已跟踪数、提示数、非官方标记与部分收录数）。
- 数字 ID / 部分收录：`python -X utf8 scripts/audit_mirror_entities.py --json` 的 `matched_marked_partial`；或直接检索 `> 状态：部分收录`。
- 重跑时先记录 `git rev-parse HEAD` 与 `git status --porcelain`；工作区新增或改动可能改变文件数与提示/标记计数。
