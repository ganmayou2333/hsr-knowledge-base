## 三、数据源与核验

**数据源清单与优先级以 `数据来源.md` + `翻译办法.md` §二 + 行动准则 §二 为准**，本节只列红线与本地坑：

1. 数值类（生命/攻击/防御/速度/倍率/回合数）必须来自官方或权威源（官方公告 / 米游社 WIKI / hsr.nanoka.cc / StarRailRes）；论坛、贴吧、营销号、二手攻略只能用于找线索。
2. 官方源有**本地副本**时优先用本地（路径见 `翻译办法.md` §二）。
3. **本地两份 StarRailRes 克隆按用途分工（不要问「谁为准」）**：
   - **多语言 JSON 数据** → `G:\HSR\StarRailRes-master\index_new\`（**13 语言**：cn/cht/en/jp/kr/de/es/fr/id/pt/ru/th/vi；ZIP 快照，停 v4.5）
   - **图包与可更新副本** → `G:\HSR\StarRailRes_repo\`（**git 克隆可 pull；仅含 cn**，sparse：index_new/cn + icon + image + font）
   - 同一用途内版本冲突 → 以**版本更新者**为准（当前两者均为 v4.5，无冲突）；用途不明或出现新的不一致 → 停下问我。
4. 本地 TextMap（`temp/textmap/`）**只能用于校验措辞、补缺句、核对术语**，不能还原对话顺序——详见 `30_模块_剧情获取.md`。
5. 「前瞻 / 未上线 / 爆料」内容不得写入正式详情文件；确需记录时元信息写 `数据版本：4.6（前瞻）`，并在文末注明来源与不确定性。

## 四、五阶段交付（逐阶段验收，不得跳阶段）

### 阶段 A · 4.6 对账清单表（**禁止写数据文件**）
回答「**4.6 到底还有什么没做**」，输出三张表（模板见附录 A）：
1. **A1 库内已有 4.6**：扫描 `zh_cn/` 内 `数据版本：4.6` 的文件，按类别汇总 + 抽样路径（以实测为准）。
2. **A2 全新待建**：4.6 已上线但库内**没有**的条目（角色 / 光锥 / 遗器 / 物品 / 模拟宇宙 / 剧情 / 活动玩法 / 机制）。
3. **A3 待补字段**：库内已有 4.6 条目但字段缺失或仍是占位（缺途径 / 缺说明 / 缺星级等）。

规则：
- 每条带来源 URL；确认不了的进「待确认区」并说明卡点。
- 对 A1 已存在条目：**默认不新建文件**；内容与官方不符需修订时，先出「差异表」（文件名 / 现有内容 / 官方内容 / 建议动作）等我确认。
- **交表后停下等我确认。**

### 阶段 B · 简体中文详情文件（逐类，先 demo）
顺序：遗器 → 光锥 → 角色 → 物品 → 模拟宇宙 → 剧情文本（按 A2/A3 结果，哪类有缺口做哪类）。
- 动笔前：读 `格式规范与要求.md` 对应章节 + `10_核心` 的同类基准文件。
- 每类先交 1 个 demo；每批 ≤10 个文件停下汇报。
- **剧情文本走 `30_模块_剧情获取.md` 的专门流程**。
- **命名冲突处理**：库内部分 4.6 物品用了 `名称_ID.md`（如 `不老者的仙舟_83024.md`、`《星间启航》绘本_140621.md`），与规范 §二「重名合并为单一文件」不一致。**你按规范执行（同名合并）**，遇到与既有文件冲突时停下问我，不要擅自合并或改名。

### 阶段 C · 索引更新
- 依据 §一 的索引层级，挂进 评级索引 → 分类索引 → 主索引回链；同步数量统计。
- 需要新分类 / 新命途时先出方案（会牵动 character、lightcone 两库 + 四语言镜像）。

### 阶段 D · 四语言镜像
- **先通读 `翻译办法.md` §一~§八 + 行动准则 §三**，按四级优先级执行（官方源直填 → 机械替换 → 片段清单 → LLM 兜底）。
- 章节标题、字段名、专有名词以 `翻译办法.md` §七 + 同类存量镜像为准，**不得自创译法**。
- 正文必须为官方文本；拿不到就保留原文 + `<!-- 待译 -->`，禁止机翻硬凑。
- 结构基线：`en_us/relic/隧洞遗器/Wavestrider Captain.md`（现存镜像有半译残留，**照抄结构、不照抄未译内容**）。

### 阶段 E · 自检与日志
1. **脚本运行目录（两个脚本要求相反，勿混淆）**
   - `scripts/verify_fields.py`：分类判断基于 `character/`、`items/` 前缀，**必须在 `zh_cn/` 目录下运行**，否则全部文件被判为 `other` 而跳过（空跑）
   - `scripts/verify_links.py`：以 `os.walk('.')` 建「已存在文件集」，**必须在仓库根 `G:\HSR` 运行**；若误在 `zh_cn/` 下运行，链接中的 `zh_cn/` 前缀会全部匹配失败 → **误报近万条死链**（2026-10-01 实例：9838 条误报）
   - **优先用 MCP**：`kb_validate_fields` / `kb_validate_links` 统一以 `HSR_ROOT` 解析，规避以上两个坑
2. 两脚本的 `skip_dirs` 只排除了 `StarRailRes_repo`，**未排除 `StarRailRes-master`**（含 `README.md`），全库计数会受影响；发现异常先告诉我，不要改脚本。
3. 能跑脚本就贴完整输出；不能跑就人工核对并说明方式。
4. `update.md` 追加日志：格式照抄其顶部既有条目（`## YYYY-MM-DD HH:mm` + 加粗主题 + 无序列表）。
5. 交付统计：新增文件数（按类型/语言）、修改文件数、待补充清单。
