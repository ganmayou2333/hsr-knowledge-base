> **装载条件**：任务涉及 `zh_cn/quest/剧情文本/` 下主线 / 同行 / 冒险任务正文时，连同 `10_核心` + `20_参数` 一起装载。

## G.1 数据源与优先级

| 优先级 | 来源 | 用途 | 能否还原对话顺序 |
|---|---|---|---|
| 1 | 米游社 WIKI 任务页（`bbs.mihoyo.com/sr/wiki/`，浏览器逐页读取） | 正文对话主体 | ✅ 有序 |
| 2 | B 站 Wiki **MediaWiki API**（`wiki.biligame.com/sr/api.php?action=parse&page=<页面名>&prop=wikitext&format=json`） | **子任务链 / 元信息**（编号、前置·后续、出场人物、任务地区） | ⚠️ 仅结构；**该 wiki 无对话正文**（页面内为 `{{任务描述|描述内容\|…}}` 占位符，浏览器渲染也拿不到） |
| 3 | 官方 TextMap（本地 `temp/textmap/`） | **仅校验措辞、补缺句、核对术语** | ❌ 无序（见 G.3） |
| 4 | 官方版本更新说明（`sr.mihoyo.com/news/*`） | 任务概述、节点大纲 | ⚠️ 只有大纲 |

**结论：对话正文只能来自优先级 1（米游社 WIKI）；顺序由该页出场顺序决定。B 站 Wiki 仅用于取子任务链与元信息——用 API 免渲染直取 wikitext，不要用浏览器抓渲染页。**

> 实例（2026-09-30 实证）：4.6 系列任务「月升之前，与兽共舞」的 5 个子任务均可经 API 取到编号/前置·后续/出场人物；但其「剧情内容」章节全部只有 `{{任务描述|描述内容|任务地区名-地图名}}` 占位符 → 对话正文不在该 wiki。

## G.2.1 TextMap 渲染标签与换行处理约定（Lead 裁定，2026-09-30）

逐字回填 TextMap 原文时，按下列规则转换（避免每次临场决定）：

| TextMap 标记 | 处理 |
|---|---|
| `<color=…>…</color>`、`<size=…>…</size>`、`<icon …>`、`<unbreak>…</unbreak>` | **去标签，保留文字**（如 `<unbreak>45%</unbreak>` → `45%`） |
| `<b>…</b>` | **去标签，不加粗**——理由：本库 quest 文件中 `**…**` 已专用于「说话人」标记（如 `**虚照**：…`），原文强调不再二次表达 |
| `<i>…</i>` | 去标签，保留文字（不加斜体） |
| `\\n` / `\n` | 转为真实换行；空行保留原段落分隔 |
| 标注 | 行尾加 `<!-- 原文含排版标签，已去标签 -->` |
| **多行原文** | **续行缩进 2 空格**，保持在列表项内；若段落过长，改用引用块 `>` 呈现 |

## G.3 铁律：TextMap **不能**还原对话顺序（已实测，勿再尝试）

- 本地路径：`temp/textmap/TextMapCHS.json`（简体）、`TextMapEN.json`、`TextMapJP.json`、`TextMapKR_0.json`、`TextMapCHT.json`
- 格式：每行一条 `"<hash>": "<文本>",`（已格式化，可 grep / 逐行读取）
- **实测证据**：同一任务的 7 条台词 hash 分布在第 124346 ~ 423793 行（跨 30 万行），且**不按数值有序**（1.6×10¹⁹ 出现在 1.17×10¹⁸ 之前）→ **按行号排序同样无法还原顺序**
- 因此：**禁止**用 TextMap 生成或推测对话顺序；**禁止**把主题片段拼成正文并声称按场景顺序
- TextMap 的合法用法只有三种：
  1. **核对官方措辞**：拿到 wiki 正文后，逐句在 TextMap 中检索确认
  2. **补缺句**：wiki 缺句时，从 TextMap 补入并标注 `（hash <数字>）`
  3. **术语校验**（见 G.4）

> 本地**没有任务脚本**（已全库扫描 `*Task|Quest|Dialog|Story|Mission|Level*.json`，0 命中；StarRailRes `index_new` 24 个 JSON 无任务数据），不要假设存在。

## G.4 术语校验（必做）

正文中的专有名词（BOSS / 怪物 / 组织 / 地点 / 概念）必须与 TextMap 原文一致。

> 实例（本库真实教训）：官方原文为「**兽蜕**」（TextMapCHS.json：「在兽蜕冲破封印前…」），曾误写为「贪饬受退」并扩散到 3 个文件。

校验方法：在 TextMap 中检索该词 → 确认存在且语境吻合。检索不到时：保留原文并标注「待核验」，同时问我，**不要自行定名**。

## G.5 状态标记与诚实原则

| 状态 | 含义 | 允许内容 |
|---|---|---|
| `v0.1` | 骨架 | 任务描述 + 节点大纲 + （可选）主题片段清单 |
| `v0.2` | **结构完整、正文待补** | v0.1 全部 + **官方子任务链**（编号 / 名称 / pageid / 出场人物） |
| `v1.0` | 完整 | 按场景分节的逐句对话 `**角色名**：台词` |

> 状态必须与文件实际一致；**只有部分场景完成时不得标 `v1.0`**（用 `v0.2` 并注明已完成场景）。

- 拿不到有序来源时：**保持 v0.1**，只交「主题片段清单（每条带 hash 出处）」，并在文件内写明「对话顺序待有序来源还原」。
- **禁止**：自行编排顺序、补写台词、把 v0.1 标成 v1.0、用视频/实况口述当作官方原文。
- 每个 hash 引用写成 `（hash <数字>）`，便于复核。
