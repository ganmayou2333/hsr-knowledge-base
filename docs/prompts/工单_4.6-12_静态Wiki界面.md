## 一、架构决策（Lead 已定，按此执行）

```
wiki/
├── index.html            ← 首页：主索引导航 + 搜索框 + 死链提示
├── assets/style.css      ← 样式（浅/深色随系统，响应式）
├── assets/app.js         ← 搜索 + 侧栏折叠 + 主题切换（vanilla JS，零依赖）
├── build_wiki.py         ← 生成器（零依赖，可重复运行）
└── （生成物，不入库）
    ├── pages/<原路径>.html   ← 每页一个 HTML，保留原目录结构
    └── data/titles.json      ← 标题索引（前端搜索用）
    └── data/link_report.json ← 双链健康报告
```

**提交策略（关键）**：
- **入 git**：`wiki/index.html`、`wiki/assets/*`、`wiki/build_wiki.py`、`.github/workflows/pages.yml`
- **不入 git**：`wiki/pages/**`、`wiki/data/**`（体积大）→ 写入 `.gitignore`，由 Actions 生成后发布

---

## 二、页面要求

| # | 要求 |
|---|---|
| 1 | **面包屑**：`首页 / <分类> / <子类> / <页面名>` |
| 2 | **md → HTML**：支持标题（`#`~`####`）、表格、有序/无序列表、引用、加粗、行内代码、代码块 |
| 3 | **双链解析**：`[[zh_cn/a/b\|显示名]]` → `<a href="pages/zh_cn/a/b.html">显示名</a>`；**目标不存在时加 `class="dead"` 并标红**；表格内 `\|` 转义须正确处理 |
| 4 | **页脚**：完整呈现该页头部元信息（数据来源 / 数据版本 / 实体ID / 官方Wiki） |
| 5 | **上一篇 / 下一篇**：按同目录文件名排序 |
| 6 | **返回主索引**链接（页面内已有则保留） |
| 7 | **响应式**：窄屏折叠侧栏 |
| 8 | **零依赖**：不引 CDN、不装 npm 包；纯静态、相对路径，**file:// 可直接打开**（不得依赖 fetch/XHR） |

## 三、搜索

- 前端用 `data/titles.json`（字段：`path` / `title` / `category` / `lang`）做**标题与路径模糊搜索**
- **全文搜索本轮不做**，在 README 标注为后续扩展

## 四、双链健康（与 Part A 联动）

- 生成时统计并写入 `wiki/data/link_report.json`：`总链接数` / `死链数` / 死链清单（来源文件 → 目标）
- 死链在页面上**标红**；首页展示「死链 N 条 → 查看清单」

## 五、交付与托管

1. `wiki/build_wiki.py`：`python wiki/build_wiki.py` → 生成 `pages/` 与 `data/`
2. `.github/workflows/pages.yml`：push 到 `main` 时用 Python 生成并发布到 GitHub Pages
3. `wiki/README.md`：本地预览方法（`python -m http.server` 或直接打开 `wiki/index.html`）+ Pages 启用步骤
4. 首次生成后**报告产物体积**（页数 / MB），供 Lead 判断是否需要裁剪

## 六、红线

1. **不得修改任何现有 `.md`**
2. 生成物 `wiki/pages/**`、`wiki/data/**` 必须进 `.gitignore`
3. 不得引入外部依赖（CDN / npm / pip）
4. 死链只**标记**不擅自修（修复走独立工单）
