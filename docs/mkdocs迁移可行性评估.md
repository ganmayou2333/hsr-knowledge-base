# MkDocs 迁移可行性评估（Lead）

> 建立：2026-10-03 ｜ 维护：Lead ｜ 触发：用户问「有什么构建 Wiki 好用的编程语言」，选做迁移评估
> 结论速览：**技术上可行，但成本集中在两处非标准需求（实体ID URL、五语言镜像）**；**不建议现在迁移**，详见 §5。

---

## 一、基准：现有自研生成器（实测）

| 项 | 实测 |
|---|---|
| 生成器 | `wiki/build_wiki.py` · **283 行** · **零外部依赖**（仅 Python 标准库） |
| 构建耗时 | **10.3 / 10.5 / 10.5 s**（6,665 页，3 次实测） |
| 产物 | `wiki/pages/**/*.html` **6,665**、`wiki/data/{titles,link_report}.js/json` |
| 死链 | `link_report.dead` = **0**（硬红线） |
| 离线 | **`file://` 直接可用**（无服务器、无 CDN） |

**关键两个数**：

- **表内转义的 `\|` 共 13,387 处**（五语言合计）——这是 Obsidian 双链插件最容易翻车的点。

## 三、能力对照（需求 × MkDocs 现状 × 缺口）

| # | 本库需求 | MkDocs / Material 现状 | 缺口 |
|---|---|---|---|
| 1 | `[[路径\|显示名]]` 双链 | **有插件**：[mkdocs-roamlinks-plugin](https://raw.githubusercontent.com/Jackiexiao/mkdocs-roamlinks-plugin/master/README.md)，另有支持特殊字符的 [‑extra 分支](https://pypi.org/project/mkdocs-roamlinks-plugin-extra/) | **表内 `\|` 与全角字符需逐个实测**（13,387 处） |
| 2 | **详情页 URL = 实体ID**（5,413 页 / 8,486 入链） | **无现成支持**（MkDocs 按文件路径出页） | **必须自研 hook 或放弃** ← 最大成本项 |
| 3 | 死链口径 `dead = 0`（硬红线） | MkDocs **不报死链** | 需保留现有 `verify_links.py` / 自研 hook |
| 4 | 五语言镜像（30,070 文件、同名中文文件） | **有插件** [mkdocs-static-i18n](https://pypi.org/project/mkdocs-static-i18n/0.41/) | 需按插件目录约定重组或配置；每种语言要各自 nav |
| 5 | `file://` 离线可用 | **Material 内置 [offline 插件](https://raw.githubusercontent.com/squidfunk/mkdocs-material/master/docs/plugins/offline.md)** | 无（开启即得） |
| 6 | 搜索 / 导航 / 主题 | **开箱即有** | 无 |
| 7 | CJK 文件名 / 全角引号 URL | 走标准 Markdown 链接与 slug | 需实测（本库曾因未编码破链，D-030） |
| 8 | 图片零入库（D-014/15），图标构建期注入 | 需重做 `copy_icons` 逻辑 | 中等 |
| 9 | Obsidian 库为**唯一真相** | MkDocs 仅作构建层，不冲突 | 无 |
| 10 | `实体ID` 已在元信息（可作为页面显示的 ID） | 直接用 | 无 |

## 四、成本清单（**工作量为估算，非实测**）

| 档 | 事项 | 估算 |
|---|---|---|
| A. 直接可得 | 开 offline 插件；主题/搜索/导航 | **0.2 天** |
| B. 装插件即可 | 双链插件；i18n 插件 | **0.5 天**（装 + 配置） |
| C. **必须实测** | 表内 `\|`（13,387）、全角引号/CJK 路径、`file://` 下搜索索引 | **1–2 天**（含回归） |
| D. **必须自研** | **ID URL 映射**（5,413 页 + 8,486 入链）或**放弃该特性** | **1–3 天**（风险最高） |
| E. 结构适配 | 五语言 nav/目录约定重排（30,070 文件） | **1–2 天** |
| F. 校验重建 | 死链报告口径、`verify_fields` 对接、图标注入 | **1 天** |
| **合计** | — | **约 5–10 天**，其中 **D 为唯一高危项** |

## 五、结论与建议

1. **不建议现在迁移。** 现行自研生成器**已 100% 满足**本库四条硬需求（双链、ID URL、死链口径、镜像同构），且离线可用、零依赖、10 秒构建。迁移的**收益主要是「主题/搜索开箱即用」**，而**成本主要是把已经解决的问题重做一遍**。
2. **若迁移，先砍 ID URL**：ID 已在 `> 实体ID：` 元信息中，页面内显示即可；URL 回到文件路径可省掉 D 档全部成本与风险（5–10 天 → 3–5 天）。
3. **折中方案（推荐替代）**：**不迁移**，但把 Material 的两个长板**在当前自研生成器里低成本补齐** —— ① 站内搜索（已有 `data/titles.js`，加一个前端过滤即可）② 侧边导航（按目录生成树）。这样拿到 80% 体验提升，0 迁移风险。
4. **何时才该迁**：库规模到 **3 万页以上**、或需要**多人网页端协作编辑**（那时应上 DokuWiki / Wiki.js，而非 MkDocs）。
